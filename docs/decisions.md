# Phase-one decisions

## Engine and physics

Defold **1.14.0 stable**, published 12 October 2026. Bob reports engine commit `a81dbb0478e8b73931dc2d671563204f6ac0ef82` and channel `stable`. Java 25 is required. Toolchain version and official GitHub release asset SHA-256 live in `tools/defold-version.env`.

Use the integrated **Box2D 3.1.0** backend, selected explicitly by `main/box2d3.appmanifest`. Defold 1.14.0 pins this version in [its core source](https://github.com/defold/defold/blob/1.14.0/external/box2d/Box2D/src/core.c). Upstream Box2D 3.1.1 is newer, but cannot be substituted as a Lua package; an exact 3.1.1 upgrade requires a stable Defold SDK with that integration. The initial prototype used the default legacy 2.2.1 backend conservatively; the owner subsequently requested and authorized this migration to the supported integrated version. No alpha engine or external physics library is used.

Version-specific API evidence:

- [1.14.0 physics bindings](https://github.com/defold/defold/blob/1.14.0/engine/gamesys/src/gamesys/scripts/script_physics.cpp): `physics.JOINT_TYPE_WHEEL`, `create_joint`, `set_joint_properties`; properties `local_axis_a`, `enable_motor`, `motor_speed`, `max_motor_torque`, `frequency`, `damping`.
- [Box2D 3 shape bindings](https://github.com/defold/defold/blob/1.14.0/engine/gamesys/src/gamesys/scripts/box2d/v3/script_box2d_shape_v3.cpp): `b2d.shape.set_friction(shape_id, friction)`, with handles from `b2d.body.get_shapes`. Called on freshly spawned tires before contact.
- [Box2D 3 joint bindings](https://github.com/defold/defold/blob/1.14.0/engine/gamesys/src/gamesys/scripts/box2d/v3/script_box2d_joint_v3.cpp): `create_wheel`, `enable_motor`, `set_motor_speed`, `set_max_motor_torque`, `is_spring_enabled` and `destroy`. `enable_spring=true` is required explicitly. Defold’s high-level physics.create_joint currently disables the v3 wheel spring; the rover therefore uses the documented low-level handles.
- [Box2D body lookup](https://github.com/defold/defold/blob/1.14.0/engine/gamesys/src/gamesys/scripts/box2d/script_box2d.cpp): `b2d.get_body(collision_object_url)`.
- [Window bindings](https://github.com/defold/defold/blob/1.14.0/engine/gamesys/src/gamesys/scripts/script_window.cpp): focus events and `window.get_safe_area()`.

Official manuals consulted: [Bob builds](https://defold.com/manuals/bob/), [HTML5](https://defold.com/manuals/html5/), [Android](https://defold.com/manuals/android/), [physics](https://defold.com/manuals/physics/), [joints](https://defold.com/manuals/physics-joints/), [touch](https://defold.com/manuals/input-mouse-and-touch/).

## Driving and lifecycle

Three dynamic bodies, two wheel joints and 15 static track slabs. Pixel-to-meter scale 0.01; base gravity 480 px/s² (4.8 m/s²), with arcade tuning rather than literal lunar gravity. Wheel motor angular speed is rad/s; motor/brake torque is N·m; spring tuning is Hz and damping ratio. Grip is fixture friction. Air control applies a physical force couple, limited to angular speed 2.5 rad/s. A tunable-strength feedback assist targets +0.35 rad nose-up under gas and -0.35 rad under brake, with angular damping; this keeps held pedals from continuously flipping the rover. Coasting provides no air torque. Both pedals pressed means brake wins and nose-down air input. Coasting disables wheel motors.

Physics runs at 60 Hz; engine `max_time_step=0.05` discards excess hitch time, bounding catch-up to roughly three fixed steps per render update. Focus loss disables rover bodies and clears input. Resume is explicit, with no wall-clock catch-up. Bodies are re-created on restart, destroying old joints first. All tuning is staged until an explicitly labeled restart, including friction to avoid stale cached contacts.

The render projection keeps world height at 720 units and reveals more terrain on wide screens. Camera offset places the rover near the left third at 16:9, with exponential follow and no spring overshoot. UI uses actual window size and platform safe-area insets; landscape is the intended orientation. Atlas sprites, 3 active dynamic bodies, small static geometry and no particles aim for 60 FPS; this is not a device performance claim. All gameplay assets are bundled and use no network services. A first browser load requires HTTP access; persistent offline reloading is not implemented in this phase.

## Licensing and references

No project license was supplied. Project and original artwork licensing remains an owner decision. Both owner reference images were visually inspected for the phase-one correction; their original files cannot be downloaded in this environment. See [reference observations and asset provenance](references/README.md). The corrected assets are original modular illustrations generated by the committed Pillow authoring script, with no reference-image extraction. The unmodified bundled DejaVu font carries its actual upstream notice separately.

Graphics are separate from Box2D. The phase-one correction used procedural placeholder art; the subsequent owner-requested integration uses all 18 Imagegen source PNGs from PR #13. Source originals and their manifest are preserved, while small runtime derivatives, four ordinary 2D atlases, pivots and source-eye transforms are reproducible. See [runtime specification and budgets](../assets/sprites/mondpost/README.md).

Physical bodies, colliders, wheelbase, 24px tire radius, joints, input arbitration and driving parameters remain unchanged. Only cosmetic component positions/layers change to assemble chassis, driver and cargo. Shocks extend from a visible 38px bracket along the real joint axis to each real wheel center; the actual rest anchors remain unchanged. The eight-sprite dust pool is visual only, gated by ground proximity and speed and cleared on pause/focus/restart/finish. Solar station, rocks, details and finish flag have no new colliders or interactions.

Source mountains are not certified seamless: overlapping, mirrored, feathered cards avoid hard transitions on the fixed track. Page-size atlas fields produce texture arrays in 1.14.0 even with one page, incompatible with the existing materials; the shipped atlases are verified single-page ordinary 2D textures. No dependency or engine updates accompany this integration.

## Renovate

Supported managers only: npm, GitHub Actions, custom regex with github-releases datasource for `defold/defold`. Stable numeric versions only. No automerge, and major updates require dashboard approval. Engine PRs must manually update the checksum from authoritative release metadata; stale checksums intentionally fail builds. Required repository CI applies to update PRs. The custom extractor is validated locally by invoking Renovate’s own extraction function with RE2 and schema validation. The installed bot must still run in GitHub to confirm its app permissions/onboarding state.

HTML5 uses a lightly customized copy of Defold's built-in engine template (`main/index.html`) for lifecycle bridging. It remains Defold template code under the [Defold License](https://defold.com/license/); it is not a gameplay framework or WebView wrapper. Native focus events use the Lua listener directly; the HTML5 bridge forwards browser blur/hidden-tab events to Defold's canvas focus callback. The project/asset licensing decision remains open independently.

Backend-unit correction: the supported low-level `b2d.joint` API scales torque by physics.scale on creation and updates. Divide panel torque in N·m by 0.01 before passing it in. `ApplyForce2D` also multiplies force by scale; the air controller compensates explicitly. Unlike the old partial joint property updates, the dedicated setters leave spring parameters unchanged. Verify conversions again on engine/backend updates.

Backend selection produces a custom engine from Defold’s official build service. The app manifest lists the supported HTML5, Android, desktop and iOS targets; no iOS build is required in this phase. The manifest is based on Defold’s version-pinned Box2D 3 example with empty legacy test fields removed. Bob does not honor HTTPS_PROXY for its native client, so a short-lived loopback bridge forwards to the fixed official HTTPS destination using normal certificate verification. CI without an HTTPS proxy uses the official endpoint directly.
